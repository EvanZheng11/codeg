# macOS Finder / 右键打开目录 → 自动加入工作区并开会话

- 日期：2026-09-30
- 状态：设计已确认，待实施
- 影响面：`src-tauri`（桌面模式 macOS 分支）为主；无数据库结构变更、无数据删除
- 非 macOS 平台：行为保持不变

## 1. 背景与目标

用户在 macOS Finder 中选中一个目录，通过「打开方式 / 超级右键 → codeg」唤起应用时，期望：

1. 该目录自动出现在 codeg 的工作区中（若尚未加入）；
2. 随后使用**当前默认智能体**直接打开一个新会话，无需再手动选择目录与智能体。

目标拆成三条可验证的验收标准：

| 编号 | 验收标准 |
| --- | --- |
| A1 | 目录未加入工作区时，被加入；已加入时不重复添加、不报错 |
| A2 | 加入后自动以当前默认智能体创建一个新会话，并把窗口置前 |
| A3 | 冷启动（应用未运行）与已运行两种情况下都能生效；重复事件只处理一次；无效路径忽略并写日志 |

## 2. 现有链路

实施时复用的都是已有能力，本设计不新增 IPC 通道、不新增独立进程。

### 2.1 Tauri macOS 的 `Opened` 事件与 `file://` URL

- macOS 通过 LaunchServices 把「用本应用打开」的请求投递给应用。Tauri 2 在 macOS 上以 `RunEvent::Opened { urls }` 暴露该请求，`urls` 为 `file://...` 形式的 URL 列表（多选时为多个元素）。
- 先决条件：`Info.plist` 中声明可接收目录类型（`CFBundleDocumentTypes` 或等价的 `tauri.conf.json` bundle 配置）。缺此项时 macOS 不会把 Finder 请求投递给本应用——这是本方案唯一的**配置层前置改动**。
- 冷启动时，事件可能在窗口、数据库、事件发射器就绪之前到达；已运行时事件直接进入事件循环。
- 已运行但窗口被隐藏/最小化时，需要显式显示并聚焦窗口，否则用户看不到新会话。

### 2.2 `open_folder_in_workspace`

- 桌面模式下把目录加入工作区的既有入口。它负责：校验目录、写入工作区记录、通知前端刷新工作区列表。
- 本设计直接复用它，不重写加入逻辑：
  - 已在工作区 → 走「已存在」分支，不新增记录；
  - 未加入 → 走新增分支。
- 判定“是否已加入”以该入口现有的匹配逻辑为准（含路径规范化），避免出现第二套重复判定规则。

### 2.3 默认智能体会话

- 前端/后端已有「创建会话」的既有路径：选定工作区 → 选定智能体 → 建会话。
- 「当前默认智能体」取应用现有的默认智能体配置项，不新增第二份默认值来源。
- 会话创建由既有链路完成；本设计只负责在目录就绪后触发它。

## 3. 推荐方案

**最小方案：在 macOS 的 `Opened` 事件回调里做「解析 → 校验 → 去重 → 加入工作区 → 开会话 → 聚焦窗口」六步，其余平台零改动。**

关键取舍：

1. **复用 `RunEvent::Opened`，不新增自定义 URL scheme。** 该事件就是 macOS 为“用本应用打开目录”提供的原生通道，自建 scheme 需要额外的协议注册与握手，收益为零。仓库已有的 `docs/url-scheme.md` 描述的是另一条链路，本设计不修改它。
2. **不做前端中间层。** 事件在 Rust 侧处理完，最终通过已有的事件机制（`EventEmitter`，桌面为 Tauri 事件）驱动前端创建会话，避免新增前后端往返协议。
3. **冷启动用一次性缓冲队列。** 事件早于就绪时先入队，初始化完成后统一冲刷；就绪后事件直接处理。避免为冷启动写第二套流程。
4. **去重放在路径规范化之后。** 先 `file://` 解码 + 规范化，再去重，否则同一目录的不同写法（`/var` 与 `/private/var`、结尾斜杠、大小写）会被判为两次。
5. **多选目录时只为一个目录开会话。** 工作区加入按顺序对每个有效目录执行；会话只为第一个成功处理的目录打开，避免一次多选弹出 N 个会话。

## 4. 数据流

```
Finder 右键「打开方式 → codeg」
        │  LaunchServices（file:// URL 列表）
        ▼
macOS RunEvent::Opened { urls }        ← 冷启动与已运行共用此入口
        │
        ▼
[1] 解析 URL → 本地路径
        · 仅接受 file:// 前缀，其余丢弃
        · 百分号解码（含空格、中文、非 ASCII）
        ▼
[2] 校验
        · canonicalize 规范化
        · 必须是存在的目录（is_dir），否则忽略
        ▼
[3] 去重
        · 同一批次内重复的规范化路径只留一份
        · 已在工作区中的目录不重复加入
        ▼
[4] 加入工作区：open_folder_in_workspace(规范化路径)
        · 已在工作区 → 已存在分支，幂等
        ▼
[5] 打开新会话：取当前默认智能体 → 在 [4] 的目录上创建会话
        · 仅对第一个成功处理的目录执行
        ▼
[6] 显示并聚焦主窗口（隐藏/最小化时同样生效）
        ▼
前端经既有事件机制刷新工作区列表与会话视图
```

冷启动与已运行的分歧只体现在第 0 步：

| 场景 | 行为 |
| --- | --- |
| 应用未运行 | 事件先入缓冲队列；窗口、数据库、事件发射器就绪后冲刷队列，再走 [1]–[6] |
| 应用已运行（含隐藏/最小化） | 直接走 [1]–[6]，末尾聚焦窗口 |

## 5. 错误处理

原则：**无效输入只记日志、不弹错、不中断**；能确定是用户意图的操作则尽量完成。

| 情况 | 处理 | 日志级别 |
| --- | --- | --- |
| `urls` 含非 `file://` 项 | 忽略该项，继续处理其余 | `warn` |
| 百分号解码失败 | 忽略该项 | `warn` |
| 路径不存在 | 忽略该项 | `warn` |
| 路径是文件而非目录 | 忽略该项 | `warn` |
| 无读取权限 / `canonicalize` 失败 | 忽略该项 | `warn` |
| 整个事件无有效目录 | 不做任何事，正常返回 | `info` |
| 目录已在工作区 | 视为成功，跳过加入，继续开会话 | `info` |
| 加入工作区失败（IO/DB 错误） | 记 `error`，不为该目录开会话；其余目录继续 | `error` |
| 创建会话失败 | 记 `error`；目录已在工作区，用户可手动开会话 | `error` |
| 事件早于初始化完成 | 入缓冲队列，就绪后冲刷 | `info` |
| 非 macOS 平台 | 事件处理代码不编译、不注册，行为与改动前一致 | — |

日志统一带上前缀与原始 URL，便于排查（例如 `open-finder-directory: skip <url>: not a directory`）。

## 6. 测试计划

### 6.1 自动化

- Rust 单元测试（可纯函数化，不需要起窗口）：
  - `file://` URL → 路径解析，含空格、中文、`%20`；
  - 非 `file://` input 被丢弃；
  - 规范化后同一路径的多种写法只产生一个结果（去重）;
  - 不存在的路径与文件路径被过滤；
  - 空列表、全无效列表不产生副作用。
- 命令：
  - `cargo test --features test-utils`（在 `src-tauri/`）
  - `cargo clippy --all-targets --features test-utils -- -D warnings`
  - `cargo check --no-default-features --bin codeg-server`：确认服务器模式不受影响（该事件属于桌面 macOS 分支）

### 6.2 手动测试矩阵（必须在真机 macOS 执行）

| # | 前置 | 操作 | 期望 |
| --- | --- | --- | --- |
| 1 | 应用未运行，目录未加入 | Finder 右键 → codeg | 应用启动，目录加入工作区，默认智能体新会话打开，窗口置前 |
| 2 | 应用已运行，目录未加入 | 同上 | 目录加入，新会话打开，窗口置前 |
| 3 | 应用隐藏/最小化 | 同上 | 窗口恢复并置前 |
| 4 | 目录已在工作区 | 同上 | 不重复添加，仍打开新会话 |
| 5 | 同一目录连续触发两次（快速双击） | 同上 | 只加入一次、只开一个新会话 |
| 6 | 选中文件（非目录） | 同上 | 无会话、无报错，日志有 `warn` |
| 7 | 选中不存在的路径（触发后立即删除） | 同上 | 忽略并记日志 |
| 8 | 多选两个目录 | 同上 | 两个目录都加入工作区，只开一个会话 |
| 9 | Windows/Linux 构建 | 构建并运行 | 「打开方式」行为与改动前一致，无新事件处理 |

### 6.3 回归

- 工作区列表、会话列表在事件处理后正常刷新，无重复条目。
- 从 UI 打开目录的原有流程不受影响。

## 7. 非目标

- 不支持 Windows / Linux 的「打开方式」或右键集成。
- 不支持「打开文件」（只处理目录；文件一律忽略）。
- 不新增自定义 URL scheme 或命令行参数入口。
- 不实现 Finder 扩展、服务菜单、工具栏按钮。
- 修改 `docs/url-scheme.md` 描述的既有 scheme 链路。
- 不为多选目录逐个创建会话。
- 不改数据库结构、不做数据迁移。

## 8. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| `Info.plist` 目录类型声明配置错误或缺失 | macOS 根本不投递事件，功能完全失效 | 该项作为实施第一步单独验证；用测试矩阵 #1 确认 |
| 冷启动事件早于初始化 | 事件丢失或 panic | 缓冲队列 + 就绪后冲刷；初始化完成前不触碰数据库 |
| 事件重复投递 | 重复加入、一次操作开多个会话 | 规范化后去重；在同一批次内和跨批次均生效 |
| 路径规范化不一致（符号链接、`/var` vs `/private/var`、大小写） | 判定“已在工作区”失败，产生重复条目 | 统一在入口做 `canonicalize`，复用 `open_folder_in_workspace` 现有的匹配逻辑 |
| 默认智能体未配置 | 无法开会话 | 记日志并保留目录已加入的事实；不弹错 |
| 桌面/服务器双模式编译差异 | 服务器模式编译失败 | 事件处理代码置于 macOS + 桌面 feature 条件下；用 6.1 的命令验证 |
| 无目录可聚焦时强聚焦窗口 | 用户被无意义地打断 | 仅在有有效目录时才聚焦 |

## 9. 实施顺序

1. `Info.plist` / bundle 配置声明可接收目录类型；
2. `Opened` 事件接入 + 缓冲队列（冷启动/已运行统一入口）；
3. URL 解析、规范化、校验、去重（纯函数，先写单测）;
4. 复用 `open_folder_in_workspace` 加入工作区；
5. 触发默认智能体新会话 + 聚焦窗口；
6. 手动测试矩阵 #1–#9。
